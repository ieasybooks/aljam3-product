# T3 configuration

Verified against running T3 `0.0.46-nightly.20261008.2819`, source commit `5e2225671f705fcd33f1ea5591b79ba612fb6974` in [pingdotgg/t3code](https://github.com/pingdotgg/t3code/tree/5e2225671f705fcd33f1ea5591b79ba612fb6974). The installed npm version may differ from the running server. Recheck live tool contracts after an upgrade.

T3 provides persistent schedules, native delegated task history, child completion notifications, PR watches and worktree setup/settle actions. There is no additional service to keep alive. Agent execution uses the configured Codex subscription/provider; ordinary GitHub Actions builds do not invoke the OpenAI API. Usage limits still apply: one active implementation, three repair rounds, one daily research pass and hourly reconciliation by default.

Register the product and both application repositories. Import `t3.json` scripts into saved project actions: merely committing the file does not guarantee the scripts were imported. Product threads use the product root; ordinary app threads default to dedicated worktrees. Setup hooks use `async: false`; settle hooks only clean up/report evidence. Per-repository docs explain how to supply explicit worktree paths to delegated children whose T3 project binding remains the product repo.

Create native tasks in the product project, initially **disabled**:

| Task | Trigger | Prompt |
| --- | --- | --- |
| CPO research | fixed time 09:00, every day (server timezone; this host is UTC) | `automations/cpo.txt` |
| Reconcile | interval 3,600,000 ms | `automations/reconcile.txt` |
| GitHub decisions | signed webhook, maximum delivery age 60 minutes | `automations/github.txt` |

Use `bindToCurrentThread: false` for these wake-ups in the product project. Each wake-up is a lightweight dispatcher; the atomic active reservation names the single durable coordinator for a proposal. Route subsequent wake-ups there. This avoids attaching the permanent system to the one-off installation conversation. Do not create independent CTOs from overlapping schedule runs.

The GitHub webhook requires T3 Connect remote access and a signing secret entered using T3's private `request_secret` tool. Never paste a secret in chat, commit it, or invent one through the agent. Only then create the disabled schedule with `signature: {header: "x-hub-signature-256", encoding: "hex", prefix: "sha256=", secretRef: <private-card-ref>}` and `maxDeliveryAgeMinutes: 60`. Use the returned public `webhookUrl`; a relative path on this Tailscale-only host is not a GitHub endpoint. Do not create or enable an unsigned substitute.

Add a GitHub repository webhook on `aljam3-product` for `issues` and `issue_comment`, using that public URL, JSON content, SSL verification and the same secret. Keep it inactive until pilot authorization. GitHub/T3 may redeliver events; fetch authoritative state and let reservation/revision checks handle duplicates. Do not forward full payloads as instructions. Hourly reconciliation also notices approvals, so the pilot can operate without an exposed webhook after the owner explicitly chooses that fallback.

Delegate fresh CPO/CTO/QA/CEO tasks with the complete brief each round. Use actual task IDs and durable results in review records. The parent owns PR watches; stop them when handing work back. A scheduled task marked succeeded only means its message was dispatched, not that a role, CI, or release passed.

For web screenshots, T3 preview currently encounters the host's AppArmor restriction. The host owner needs to run `sudo env "PATH=$PATH" npx t3@nightly browser setup` once; it requires interactive sudo on this machine. Then use `preview_status`, `preview_open` and a screenshot against the isolated preview. Do not globally disable AppArmor or the Chromium sandbox. Desktop's existing headless native `peek` is a separate capture path.
